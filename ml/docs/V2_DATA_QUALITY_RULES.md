# V2 Data Quality Rules — classification criteria

Written before scoring any candidate, so the classification is rule-driven, not fitted to whatever looked good in the search results. Applied consistently to every dataset in `V2_PUBLIC_DATASET_REGISTRY.md`.

## The core rule

**A column named `Calories_Burned`, `calories`, or similar is not evidence of ground truth by itself.** It becomes evidence only when the dataset's own documentation states, specifically, how that number was produced. "No specifics provided" is not a passing detail — it's a disqualifying one for GOLD/SILVER purposes, regardless of how plausible the numbers look.

## Tier definitions

### GOLD
Directly measured energy expenditure with a documented methodology — indirect calorimetry (VO2/VCO2 via a named device: COSMED, Oxycon, Parvo Medics, etc.) strongly preferred. Requires: participant-level rows (not just aggregate means), a stated or inferable measurement protocol, and a license that is either explicitly commercial-compatible (CC BY, CC0, MIT + real data) or at minimum clearly stated so its status can be resolved.

### SILVER
Energy expenditure that is research-derived or validated against a criterion method, but with a gap GOLD requires — e.g., calorimetry-derived but the raw calorimetry isn't retained (only a validated regression output), incomplete measurement detail, small/unclear sample, or aggregate-only reporting from an otherwise legitimate study.

### AUXILIARY
Real, useful workout/physiological data (exercise identity, sets/reps/load, IMU/motion data, heart rate, demographics) where the calorie/EE column — if present at all — is not established as ground truth per the core rule. **Never used to fit or evaluate the calorie target.** Can still be genuinely useful for other purposes: exercise ontology expansion, feature engineering ideas, sanity-checking real-world load/rep distributions.

### EXCLUDE
Any of:
- Explicitly self-described as synthetic/generated/simulated (even a well-labeled, well-licensed synthetic dataset — synthetic ground truth is not ground truth, no matter how realistic it looks).
- Calorie values explicitly labeled "estimated" with no measurement method behind the estimate.
- Wearable-device-only calorie output with no validation against a criterion method (a smartwatch's own algorithm is exactly the kind of estimate this whole project exists to beat, not a source of truth to train on).
- Undocumented calculation with no stated formula or methodology.
- License that is non-commercial, no-derivatives, unknown/unspecified with no path to resolving it, or otherwise incompatible with SK OS's commercial use.

## Special rules for Kaggle/Hugging Face specifically

1. **Visit the actual dataset card/page, every time.** Kaggle pages are JS-rendered — a plain fetch often returns only the title; use a real browser render before writing anything about a dataset's content.
2. **Search the description for self-disclosure language first**: "synthetic," "generated," "simulated," "estimated," "for demonstration," "please do not use... for research." These phrases are the fastest, most reliable EXCLUDE signal available and should be checked before anything else.
3. **A large row count is not a quality signal.** 15,000 or 20,000 rows of undocumented-methodology data is not more trustworthy than 1,001 rows of documented indirect calorimetry — it's the same EXCLUDE-tier data at higher volume.
4. **Absence of a real dataset is a valid, reportable finding.** If a systematic search across both platforms turns up nothing GOLD/SILVER, that's the honest result — not a reason to loosen the bar on a EXCLUDE-tier dataset to make the search look more productive.

## Worked example: how to test a suspicious "Calories_Burned" column (added 2026-08-16)

When a dataset's calorie column has no documented methodology, "we can't know" is not the end of the analysis — you can often **test it empirically**. Demonstrated on Hugging Face's `mnemoraorg/calorie-burnt-15k` (15,000 rows, ECL-2.0, claimed real human data, no methodology stated):

Downloaded the actual CSVs and fitted a plain linear regression of `Calories` on `Weight, Duration, Heart_Rate, Age, Body_Temp, Gender`. Result: **R² = 0.966 on held-out data.**

For comparison, our own GOLD-tier data (reis-lab, real breath-by-breath COSMED indirect calorimetry, richer exercise-specific features, properly fitted model) reaches **R² = 0.74**. Real human energy expenditure carries genuine biological noise that no feature set fully removes. A near-deterministic fit is the signature of a *formula*, not a *measurement*.

Two readings, both disqualifying:
1. The data is synthetic and the calorie column was generated by roughly the formula the regression just recovered.
2. The data is real people, but `Calories` was *calculated* from the adjacent columns (the way a fitness app computes it client-side) rather than independently measured. Training on it would teach us to reverse-engineer someone else's undisclosed formula, not human physiology.

**Rule:** when methodology is undocumented, run this check. An R² above ~0.95 from a handful of trivially-available features is strong evidence of a derived/synthetic target. Note the danger: such a dataset would likely produce an *excellent-looking* MAPE — fake precision measuring the wrong thing, undetectable from the metric alone.

## Data leakage risk — what to check before treating any two datasets as independent

- Shared author names or lab affiliations across candidate datasets (as already found between reis2017/reis2019 in V1 — numeric proof, not just name-matching, is the standard).
- Overlapping recruitment population/time window/institution stated in the methodology.
- For Kaggle/HF specifically: check whether the uploader states the data was "compiled from" or "based on" another named source (secondary repackaging of the same underlying study counts as the same source for leakage purposes, not a new independent one).

## License compatibility (carried forward from V1, unchanged)

CC BY / CC BY 3.0/4.0 / CC0 / MIT / Apache 2.0 with real (non-synthetic) data = commercially usable. CC BY-NC / CC BY-NC-ND = excluded from commercial use regardless of data quality. "License: Unknown" or unspecified = research/reference only until resolved, never treated as cleared by default.
